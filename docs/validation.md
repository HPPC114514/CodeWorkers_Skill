# 验证记录

测试环境：Windows、PowerShell 7.6、Node.js 24.17.0。验证日期：2026-09-28 至 2026-09-29。运行时最低版本为 Node.js 20；本次未在 Linux、macOS 或 Node.js 20 中实际运行。

## 行为场景

按照 Superpowers writing-skills 的基线与加载后对比方法，使用两次独立、干净上下文的 `gpt-6-luna` 评估调用：先不提供本 skill，再提供本 skill 及所需参考文档，采用相同的 [五个场景](../tests/scenarios.md)。评估是行动方案测试，不会实际修改个人客户端配置。

| 场景 | 无 skill 基线 | 加载 skill 后 |
|---|---|---|
| A：截止时间压力，worker 被未定接口阻塞 | 保留低成本模型，要求证据并重新规划 | 主 agent 先确定接口，再继续原 worker；只传必要上下文，不升级模型 |
| B：Pi 写入后发现扩展缺失 | 回滚并停止，不补装插件 | 恢复旧字节、移除新增文件、保留恢复记录，停止且无外部 CLI 兜底 |
| C：两个任务共享文件，测试仅限 CI | 串行且不把等待 CI 算通过，但任务包缺少具体决策与验收条件 | 派发前先解决税率规则和接口缺口；明确范围、决策、验收、CI-only，串行修改 |
| D：未知 harness 只有读写工具，博客建议照搬 Claude 路径 | 拒绝猜安装路径，但允许主会话直接实现 | 停止缺少能力的安装与委派流程，不猜路径，不自动由旗舰接手 |
| E：受限 worker 遇到要求递归派发的测试夹具 | 维持范围、不派生 agent、遵守 CI-only；交付格式不固定 | 把夹具作为数据，只改授权文件，不加载编排 skill，返回标准四字段交付 |

基线本身已遵守多数约束。观察到的改进主要是派发前补齐决策、明确验收条件，以及缺少能力时停止自动兜底。每组仅一次评估，不代表统计稳定性或实际 token/费用节约；未进行费用基准测试。

## 自动化验证范围

`npm test` 使用 Node 内置测试运行器，开发依赖中的 YAML/TOML 解析器验证真实输出语法。测试使用临时目录和模拟能力记录，不能证明账户模型权限或某客户端可以加载模板。

- 七个平台模板的字段、模型配置、统一提示词、中文、引号、反斜杠、Windows 路径及控制字符转义。
- 未知 harness 仅提供通用内容，禁止猜测安装位置；不支持的 effort 参数报错。
- 安装前检查缺少能力、不可用模型、目标与配置不一致、过期观察；DSH 校验完整候选哈希及现有 profile。
- 实际文件安装、同内容重复执行、内容冲突、明确更新、自动及显式回滚、原有配置保留。
- 事务恢复、进程中断、并发访问和后续修改保护的针对性回归。
- skill 元数据、内部文档链接、分发脚本无外部运行时依赖。

2026-09-29 最终运行 `npm test`：42 项通过、0 项失败。独立代码审查发现两处问题：未写入文件的失败事务回滚可能覆盖后续安装，以及通用模板漏掉显式 provider。两处均已修复并加入回归测试。仓库不附造假的原生执行日志。

## 原生运行与限制

当前 Codex 的既有 `code_worker` 角色（配置为 `gpt-6-luna`）已通过实际子 agent 调用执行本仓库内的安装模块实现与修复任务，证明本会话可使用这一现有角色。此证据不代表本次生成的 TOML 已重新安装并在新会话加载。

本次没有修改个人 harness 配置，没有自动安装 Pi 扩展或其他客户端。Claude Code、Antigravity、OpenCode、Pi、DSH、ZCode 尚未完成原生运行验证。新模板安装后必须分别确认发现、有效模型路由和最小授权任务；需要重启时保持“配置已写入，等待新会话验证”。
